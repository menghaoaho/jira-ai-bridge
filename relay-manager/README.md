**[打开产品演示](https://menghaoaho.github.io/jira-ai-bridge/)** · **[查看同事安装引导](https://menghaoaho.github.io/jira-ai-bridge/install.html#demo)**

1.1预览版新增中文管理控制台和同事安装页面。演示可直接体验邀请、设备筛选、停用确认和三步安装流程；演示数据仅在当前页面生效，不连接真实电脑，也不生成可执行安装授权。

适合这样的协作方式：管理员保管云服务器，同事只需在公司 Windows 电脑上打开专属邀请链接，按页面引导完成检查、下载和安装。管理员可以查看设备状态、撤销未使用的邀请，以及单独停用已安装的电脑。

**当前为预览版部署模板。云端上线、真实Windows首次安装与重启自启尚未完成验收。** 本仓库不包含运行中的服务器配置、内网地址、安装凭证、私钥或设备数据。`203.0.113.10`与`jira.example.internal`均为示例占位地址。

## 同事怎么使用

管理员完成云端部署后：

1. 在能打开公司Jira的Windows10/11 x64电脑上，打开管理员私下发来的专属邀请链接。
2. 按页面提示下载专属安装文件，双击`Jira-Connect-Setup.cmd`并确认系统授权。
3. 等待安装工具自检完成。安装页面会跟踪这份邀请对应电脑的实际状态；只有云端回源检查通过才显示“连接成功”。
4. 之后可以关闭安装窗口。桌面会出现检查状态、修复和卸载入口。

电脑需要保持开机、唤醒且连接公司网络。锁屏不会停止转发；睡眠、关机和离开公司网络时退出转发，恢复条件后自动重连。

**下载GitHub源码或组件包本身不会获得接入权限。** 安装仍需管理员签发的专属邀请；授权默认24小时有效，仅能激活一台电脑。请勿把实际邀请链接或安装命令贴进Issue、README或公开聊天。需要直接使用命令时，可展开邀请弹窗的“高级选项”。

## 管理员能控制什么

- 创建专属安装邀请，设置设备备注及24小时、3天或7天有效期。
- 查看云端逐台验证的“正常转发、内网不可达、离线、已停用”状态。
- 撤销未使用的邀请，或让某台设备在60秒内退出转发。
- 给停用设备重新签发安装授权，旧凭证持续失效。
- 多台健康电脑共同承担转发；单台故障时由其他电脑或保留的旧通道接手。

管理入口为管理员HTTPS站点下的`/relay-admin/`，复用已有工作台管理员账号。同事入口为公网HTTPS站点的`/relay-start/`，邀请授权只放在链接片段中，不放在服务器请求网址参数里。邀请详情只返回该邀请的备注和连接状态，不返回设备秘密、电脑名称或管理列表。控制范围是转发设备接入，Jira账号和人员访问权限仍由原Jira系统管理。

## 管理员部署准备

此版本适配已有Ubuntu24.04、Caddy、Nginx、FRP及工作台管理员认证接口的环境。**不是通用云服务器一键安装器。** 当前部署工具保留旧FRP回环8082作为备用，不会重新安装Jira。

1. 在受控的本地副本中，将示例公网地址与公司Jira域名替换为自己的值；不要把替换后的私有副本推回公开仓库。
2. 确认现有Nginx站点文件、Caddy站点结构与认证接口符合`deploy.py`的检查。已有工作台会话通过本机`/api/auth/me`实时验证，不复制工作台密码。
3. 根据现场配置，复制`review.example.json`为被忽略的`review.local.json`，填入四份现用配置的SHA256摘要。安装前会逐一核对，变化时停止部署。
4. 在Windows所需脚本与反代模板完成配置后，运行`python3 build_release.py`，再运行`python3 package_server.py`。后者生成安装包及带精确摘要的部署命令；有`review.local.json`时自动打包该私有配置，否则只打包不可用于生产部署的示例文件。私有部署包只交付给自己的服务器，不上传公开Release。
5. 将生成的服务器包上传到自己的服务器`/root/`，执行同目录生成的部署命令。服务器需系统Python和`python3-cryptography`，且为x86_64架构。
6. 放行TCP7001，保留设备端口18120–18199为回环监听。完成原入口回归，再使用真实Windows电脑验证首次安装、自启和卸载。

仓库预构建组件包含示例地址，供审阅和定制；不能直接用于现有生产环境。需要分享给同事的是云端部署后生成的专属邀请链接，同事无需云服务器账号。

## 组件与接口

| 部分 | 用途 |
| --- | --- |
| `service.py` | 单次安装授权、设备凭证、OIDC签名、FRP授权和逐机健康检查 |
| `auth.py` | 每次请求核对原工作台管理员会话 |
| `router.py` | 将已授权且健康的设备加入转发池，保留旧通道备用 |
| `windows/` | 自检、受保护目录安装、SYSTEM后台任务、重连、检查修复卸载 |
| `deploy.py` | 配置摘要检查、服务部署、备份及回退 |
| `web/` | 中文控制台、三步安装向导与登录页 |

安装命令及设备秘密只保存摘要。FRP使用独立OIDC设备身份，令牌120秒有效；服务端插件同时核对设备状态、会话、代理名称和端口。设备控制、安装授权与HTTPS接口分开监听；插件仅本机可达。默认支持最多80台同时接入，停用记录保留，端口在停用超过60秒且旧监听关闭后才可回收。

Windows身份使用机器级DPAPI保护，运行配置仅管理员和SYSTEM可读。后台任务包含开机、周期补启动、故障重启和单实例保护；停止与卸载按本工具的程序路径匹配，不停止其他FRP或Nginx。

## 构建与测试

Python需要`cryptography`，可在虚拟环境中安装：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install cryptography
.venv/bin/python -m unittest discover -s . -p 'test_*.py' -v
python3 build_release.py
```

`build_release.py`从官方来源读取固定FRP0.70.1及Nginx1.30.6，验证FRP发布摘要，并以`vendor-lock.json`锁定所有组件。生成的Windows组件包包含所需程序，同事不需要安装开发工具或自行访问GitHub下载依赖。

本机安装Nginx后，可运行`.venv/bin/python integration_test.py`进行真实FRP/OIDC/Nginx双端模拟联调。`test_windows.ps1`使用PowerShell解析脚本并执行配置生成；这不能替代真实Windows上的SYSTEM、自启、安装和卸载验收。

## 回退

云端备份位于`/var/backups/jira-relay/`，仅root可访问。以root运行：

```bash
python3 deploy.py --rollback /var/backups/jira-relay/对应备份目录
```

回退恢复原代理配置并停用新增服务，保留设备审计和密钥以供受控恢复。真实生产回退尚未演练。自动回退会保留应用目录、配置目录及审计状态；如首次安装失败，管理员应先核对并归档保留的应用和配置目录，再恢复或重新部署，不能直接覆盖重装。

本模块沿用仓库MIT许可证。FRP、Nginx及其依赖的许可证随组件包一并提供。
